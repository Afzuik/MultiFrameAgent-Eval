## 4. 框架差异结论

1. **成功率：smolagents(0.90) > react(0.75)**，且差距几乎全部来自"模型答复格式"而非框架——扣掉 11 个 verifier 假阴性后：react 39/40、smolagents 38/40（真实能力几乎打平，react 唯一真实失败 0，smolagents 2）
2. **效率：react 完胜**——平均 2.4 次工具调用 / 10.2s；smolagents 8.5 次 / 20.5s（3.5 倍调用、2 倍耗时、4.7 倍 token）。极端案例：S1 tr_013 为一次退款 **204 次工具调用**（恢复路径反复重试）
3. **鲁棒性：smolagents 更"执着"**——sh_002 react 放弃而 S1 通过；但执着换来 an_004 预算耗尽（10 步跑不完 JOIN）
4. **路径保真度（F1）相近**：react 0.773 vs smolagents 0.787；多解任务上 F1 有效区分"结果对但路径不同"（如 an_007 周报，两框架 recall 均 ~0.2 但任务通过）
5. **L3 双双满分**（1.0）：难档任务两框架都稳，失败集中在"简单但要求措辞精确"的 L1/L2——评测难点从"能力"转向"表述规范"

## 6. 评测器改进清单（v1.1 建议，实验后执行）

1. **answer_checks 数字容错**：支持千分位/小数（"21,680"、"21,680.00"）——verifier 增加数字归一化匹配（去逗号/去尾零后比对）
2. **answer_checks 措辞宽松化**：tr_006/sh_014 类关键词换稳健表达（"取消"/"修改"），或由 LLM-judge 兜底
3. **工具描述补全**：`get_order_status` 描述明确"返回含收货地址/物流单号/发票信息"
4. **校验清单新增两项**（任务设计指南.md）：①答案检查对自然表述变体（含数字格式）的鲁棒性检验；②工具描述对可推断返回字段的覆盖度检验
5. **smolagents 步数预算**：an_004 显示 10 步对 CodeAgent 偏紧，可对 smolagents 组单独放宽 max_steps（如 ×1.5）或按域配置
